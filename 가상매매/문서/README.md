│   ├─ 가상매매_백테스트.py    과거 검증

│   └─ *.bat                  더블클릭 실행용

## 4. 핵심 설계 — 왜 이렇게 만들었나

> **"프로그램은 학습을 못한다. 클로드가 실행할 수 있는 코파일럿이어야 한다."**

- **Python 엔진** = 결정론적 실행기. 규칙을 실행만 한다. **학습하지 않는다.**
- **클로드/사람** = 학습층. 원장을 읽고 평가·개선안·채택/기각을 판단한다.
- 그래서 엔진은 **모든 판단 근거를 CSV로 남긴다.**

**규칙은 `jq_paper_core.py` 한 곳에만 있습니다.** 실전 엔진과 백테스트가 **같은 함수**를 부릅니다.
(실전과 백테스트가 다르게 동작하면 백테스트는 의미가 없기 때문입니다.)

## 5. ★ 이 시스템의 한계 — 반드시 읽을 것 ★

### 5-1. 백테스트가 벤치마크를 이기지 못했습니다

**전략 CAGR이 코스피 buy&hold보다 낮습니다.** (구체 수치는 `백테스트_결과.md`)
`매도규칙서.md` v2도 같은 결론을 이미 기록하고 있습니다:
*"무제한 트레일링조차 buy&hold를 못 이겼다."*

→ **이 규칙으로 매매할 근거가 현재 데이터에는 없습니다.** 그대로 보고합니다.

### 5-2. 백테스트를 믿으면 안 되는 이유

1. **유니버스 선택편향** — 유니버스를 '최근(2026) 시총 상위'로 정했습니다. 2020년엔 그걸 알 수 없었습니다. **구조적으로 낙관 편향.**
2. **생존편향** — 완전히 제거하지 못했습니다. (중도소멸 종목이 *일부* 포함되긴 했습니다)
3. **표본이 짧습니다** — 약 6.5년, OOS는 2년 남짓.
4. **그 기간이 강세장이었습니다** — 추세추종은 강세장에서 잘 보이게 되어 있습니다. **하락장 검증이 사실상 없습니다.**
5. **슬리피지 0.1%는 가정**입니다. 실제 체결은 더 나쁠 수 있습니다.
6. **시가 체결을 가정**했지만 그 가격에 그 물량이 체결된다는 보장은 없습니다.
7. **실전 ≠ 백테스트** — 매크로 게이트가 백테스트엔 미적용입니다(그 시절 데이터가 없음).
8. **다중검정을 수십~수백 번** 했습니다. 보정 후 유의하지 않다면 좋아 보이는 숫자는 우연일 수 있습니다.
9. **공개된 아노말리는 감쇠합니다** (McLean & Pontiff 2016: 발표 후 수익 **−58%**).

> **올바른 용도: "이 규칙이 명백히 망가졌는지" 확인하는 것.**
> **"이 규칙이 돈을 번다"는 증거로 쓰면 안 됩니다.**

### 5-3. 미검증 파라미터 목록

**전략의 핵심 숫자 대부분은 학술 근거가 없습니다.**

| 근거 있음 (원문 확인) | 근거 없음 (관행/휴리스틱) |
|---|---|
| 손절해야 한다는 **방향** (Odean 1998) | ATR **2.5배 / 1.5배** |
| 할로윈 계절성 (Bouman & Jacobsen 2002) | 시간손절 **20일 / 10일** |
| 아노말리 감쇠 (McLean & Pontiff 2016) | MA **20주 / 20일** |
| | **2%룰** (실무서 출처. Van Tharp는 1% 권고) |
| | 종목상한 10%, 트랙 70:30, regime 배수, 커플링 임계 |

**출처 자체가 확인 안 된 주장** (설계 근거로 쓰지 말 것):
- "dual MA > triple MA (단순함이 복잡함을 이긴다)" — **학술 출처 못 찾음.** 검색에 걸린 건 전부 트레이딩 블로그였고 서로 모순됨.
- "추세추종 승률 35~45%" — **학술 출처 못 찾음.**

→ 상세: `검증\파라미터_근거표.md`

### 5-4. 데이터 문제 (발견된 것)

- **`kospi_index_daily.csv`가 2011-08에서 잘려 있고 마지막 행이 손상**되어 있습니다. 2011~2023 (약 11.8년)이 비어 있습니다.
  → 복구: `py fetch_kospi_index_daily.py --start 1995`
  → 그 전까지는 국면 판정에 **실측 일간수익률을 누적한 경로**를 씁니다 (보간 아님. 검증 상관 0.9991).
- **`vkospi_daily.csv`가 2026-06-05에서 멈춰** 있습니다 → 30일 초과 시 매크로 게이트에서 **미사용**.
- **코스닥 테마연동 미적용** — `theme_heat` 구성종목이 대부분 코스피 대형주라 코스닥 유니버스로 못 씁니다.

## 6. +1R 절반익절이 기본 OFF인 이유

Phase 1 스펙은 "+1R 절반 매도"를 지시했지만, **`매도규칙서.md` v2 (2026-07-12)가 그 규칙을 삭제**했습니다.
근거는 진우님 **본인의 실측**입니다:

- 17,948건: 절반익절 **有** → 기대값 **−0.01R (엣지 소멸)**
- 포트폴리오 sweep: +1R 익절은 **승률 최고(44.8%)인데 기대값 최악(−0.012R)**
- **일찍 자를수록 단조적으로 나빠짐** (예외 없음)

→ 엔진 기본값 **OFF**. 쓰고 싶으면 `--half-tp`. **두 경우 모두 원장에 기록되어 사후 비교 가능합니다.**

## ⚠️ 경로 규칙 — 반드시 지킬 것 (2026-07-13 사고 후 추가)

**데이터 CSV는 진우퀀트 루트에 있고, 코드는 `가상매매\` 하위에 있다.**

```
진우퀀트\                          ← ROOT : 데이터 CSV 원본이 여기 있다
    kospi_index_daily.csv
    attribution_pit_daily.csv
    my_holdings.csv  liquidity_sector.csv  breadth_features.csv  theme_heat_latest.csv
    가상매매\                      ← PKG
        엔진\                      ← HERE : 코드
        원장\  백테스트\  검증\  문서\  실행이력\   ← 산출물
```

### 규칙

1. **경로는 `jq_paths.py` 로만 해석한다.** 상대경로·`os.path.join(BASE, ...)` 직접 사용 금지.
2. **입력 데이터**: `from jq_paths import data_path` → `data_path("kospi_index_daily.csv")`
   (루트 우선 탐색, 못 찾으면 `None`. `require_data()` 는 뒤진 경로를 전부 담아 예외를 던진다.)
3. **산출물**: `DIR_VERIFY` · `DIR_BT` · `DIR_LEDGER` · `DIR_LOG` · `DIR_DOC` 상수를 쓴다.
4. 새 데이터 파일을 추가하면 `jq_paths.DATA_FILES` 에도 등록한다.

### 왜 이 규칙이 생겼나 — 실제로 터진 사고

엔진은 원래 루트에서 **평면(flat)** 으로 개발됐다. 이후 **코드만** `가상매매\엔진\` 아래로 옮겼는데
**데이터 CSV는 루트에 그대로 남았다.** 그런데 `할로윈_검증.py` 는

```python
BASE = os.path.dirname(os.path.abspath(__file__))   # → 가상매매\엔진\
p = os.path.join(BASE, "kospi_index_daily.csv")     # → 가상매매\엔진\kospi_index_daily.csv (없음!)
```

이라서 **`cd` 와 무관하게** 항상 엔진 폴더를 뒤졌고, 조용히 `[데이터부족]` 으로 실패했다.
KOSPI 지수를 1995~2026 전 구간으로 복구해놓고도 검증이 안 돌아간 원인이 이것이다.
**산출물 경로도 같이 깨져서**, 결과 md 가 `검증\` 이 아니라 `엔진\` 에 쓰였다.

`jq_paper_core.py` 는 처음부터 `ROOT = os.path.dirname(os.path.dirname(HERE))` 로 올바르게
해석하고 있었다(그래서 엔진·백테스트는 무사했다). `jq_paths.py` 는 그 로직을 **단일 진실원**으로
끌어낸 것이다. 앞으로 경로는 여기 한 곳에서만 정한다.

### 자가 점검

```
py 가상매매\엔진\jq_paths.py
```

ROOT 가 `...\진우퀀트` 로 찍히고 데이터 파일 6종이 `O` 로 나오면 정상이다.
