## 0. 아키텍처 — 왜 이렇게 나눴나

> 진우님 통찰: **"프로그램은 학습을 못한다. 클로드가 실행할 수 있는 코파일럿이어야 한다."**

| 층 | 정체 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| **Python 엔진** | 결정론적 실행기 | 데이터 수집 → 신호 계산 → 가상 체결 → 원장 기록 → 성과 산출 | **학습하지 않는다.** 규칙을 바꾸지 않는다. |
| **클로드 / 사람** | 학습층 | 원장·성과 CSV를 읽고 평가 → 개선안 → 검증 → 채택/기각 로그 작성 | 매매를 직접 하지 않는다. |

**동일 입력 → 동일 출력 (재현 가능).** 그래서 엔진은 **모든 판단 근거를 CSV로 남긴다.**
왜 샀는지(점수·필터 통과 여부), 왜 팔았는지(어느 규칙이 발동했는지) 전부 기록된다.

### 규칙의 단일 출처 (Single Source of Truth)

```
jq_paper_core.py          ← 규칙은 여기에만 존재
  ├─ passes_L()           진입 필터 (Track L)
  ├─ passes_S()           진입 필터 (Track S)
  ├─ check_exit_core()    청산 규칙 전부
  └─ size_position()      사이징
        ↑                        ↑
   가상매매_엔진.py         가상매매_백테스트.py
   (실전 페이퍼)              (과거 검증)
```

**실전과 백테스트가 다르게 동작하면 백테스트는 의미가 없다.** 그래서 규칙을 두 번 구현하지 않는다.
셀프테스트가 "벡터화 지표 == 스칼라 지표"를 매번 검증한다.

## 1. 2트랙 구조 (매매 트랙)

> ⚠️ 용어 주의: 여기서 "트랙"은 **매매 트랙**(Track L / Track S)이다.
> `검증_결과.md`의 "검증 트랙"(검증①통합 / 검증②국면별)과 **다른 개념**이다.

**트랙을 나눈 이유**: 두 규칙을 한 종목에 섞으면 사후에 "뭐가 먹혔는지" 분리 분석이 불가능해지고, 그게 학습 루프를 죽인다. → **별도 원장, 별도 자본, 별도 성과 측정.**

| | **Track L (중기·포지션)** | **Track S (단기·스윙)** |
|---|---|---|
| **자본** | 700만원 (70%) | 300만원 (30%) |
| **진입 필터** | 주봉 20주선 위 **AND** 20주선 기울기 상승(최근 4주) | 일봉 20일선 위 **AND** 20일선 기울기 상승(5일) **AND** 상위정합(20주선 위) |
| **손절** | max(진입가 − 2.5×ATR14, 진입가 × 0.80) | max(진입가 − 1.5×ATR14, 진입가 × 0.80) |
| **트레일링** | 고점 − 2.5×ATR (래칫) | 고점 − 1.5×ATR (래칫) |
| **MA 이탈 청산** | 없음 | **20일선 종가 이탈 시 청산** |
| **시간손절** | 20거래일 ±5% 횡보 | 10거래일 ±3% 횡보 |
| **신규 편입** | **월 첫 거래일만** | **매 거래일** |
| **청산 점검** | **매 거래일 (상시)** | 매 거래일 |
| **최대 보유** | 7종목 | 5종목 |

### 상위 프레임 정합 (Track S)
Track S는 **20주선 위에 있는 종목만** 후보로 삼는다. 상위추세 역행 진입 금지.
→ 이것이 "축 분리"(상위=방향 / 하위=타이밍)이지, "지표 추가"가 아니다.

### ⚠️ 20일선 = 4주 (5주 아님)
진우님이 "20일선 = 5주봉선"이라 하셨으나 **20거래일 = 정확히 4주**다. 5주 = 25거래일.
`MA_SHORT`는 파라미터화되어 있어 25/60으로 바꿔 검증 가능하다.

### 청산 규칙 우선순위 (동시 충족 시)
```
1. 손절 (초기 손절선 이탈)
2. 20일선 종가 이탈  ← Track S 전용
3. 트레일링 (래칫된 실효손절 이탈)
4. 시간손절 (횡보)
5. +1R 절반익절  ← 기본 OFF (아래 §3)
```
**트레일링 래칫**: 실효손절 = max(초기손절, 고점 − k×ATR). 한 번 올라간 손절선은 내려오지 않는다.

## 2. 사이징

```
위험예산 = 트랙자본 × 2% × 노출배수
```

## 4. 유니버스

| | 구성 | 비고 |
|---|---|---|
| **A (코스피)** | 시총 상위 120종목 + 추세 필터 | `liquidity_sector.csv` (시총 스냅샷) |
| **B (코스닥)** | 시총 상위 40종목 + 동일 추세 필터 | **⚠️ 테마연동 미적용** |

### ⚠️ 코스닥 테마연동이 안 되는 이유 (정직하게)
`theme_heat_latest.csv` 상위 테마의 구성종목(`theme_heat_members_latest.csv`)은 **대부분 코스피 대형주**다.
상위 4개 테마 구성종목 23개 중 **코스닥 패널에 있는 건 1개뿐**이었다.
→ 최소 5종목 기준 미달 → **"테마연동 미적용"으로 표기하고 코스닥 시총 상위로 대체**한다.
→ 코스닥 전용 테마 산출물이 생기면 그때 연동한다. (`검증_결과.md` 검증대기 목록 등재)

### ⚠️ 시총은 '스냅샷'이다 — 백테스트 선택편향의 원인
`liquidity_sector.csv`의 시총은 **수집 시점 고정값**이다. 2020년 시점의 시총이 아니다.
→ 백테스트에서 이걸로 유니버스를 정하면 **선택편향(look-ahead)** 이 생긴다.
→ `백테스트_결과.md`에 명시했다. **은폐하지 않는다.**

### ⚠️ 거래대금을 시총 대용으로 쓰면 안 된다 (실측 사고)
초기 구현에서 시총이 없어 **거래대금(거래량×가격) 상위**를 대용으로 썼더니,
**투기적 동전주가 유니버스를 오염**시켰다 (ATR/가격 15~20%, 5일 만에 741→1331원 급등 종목 등).
→ 대용치 사용 **금지**. 시총 없으면 "데이터부족"으로 유니버스를 비운다.

## 6. 할로윈 계절성 — 기본 OFF

- **원출처 확인됨**: Bouman & Jacobsen (2002, AER) 37개국 중 36개국 / Jacobsen & Zhang 323년·65개시장, 겨울−여름 +4.2%p.
- **직접 검증함** (`할로윈_검증결과.md`): KOSPI 실데이터 4/4 게이트 통과.
- **그러나 기본 OFF**인 이유:
  1. **KOSPI 지수 데이터에 11.8년 공백** (2011-08 ~ 2023-06). 표본이 온전하지 않다.
  2. **공개된 아노말리** → post-publication decay (McLean & Pontiff 2016: 발표 후 수익 **−58%**).
- 켜려면: `--halloween`. 백테스트에서 ON/OFF를 직접 비교한다.
- **할로윈은 리밸런스 주기가 아니다.** 리밸은 월 1회 그대로, 할로윈은 총노출 오버레이일 뿐이다.

## 7. 한·미 커플링 — ★기록 전용. 규칙 미반영.★

> **검증 없이 규칙 추가 금지** (진우님 원칙).

- `coupling_history.csv`에 매 실행 1행 기록.
- **미국 수익률을 1일 lag 시켜 정렬**한다 (전일 미국 종가 → 당일 한국 반응). 동일 시점 정렬은 look-ahead다.
- 데이터: `시장영향_검증_kospi_raw.csv`의 `sp`·`sox` 컬럼은 **이미 전일 미국 수익률**이며(원 스크립트가 그렇게 만듦), `y_same`은 당일 한국 수익률이다. → `corr(sp[d], y_same[d])`가 정확히 요구된 정렬이다.
- **나스닥(^IXIC)은 오프라인 소스가 없어 공란**으로 남긴다. 채우지 않는다.
- 임계값(고정, 임의 해석 금지):

| state | 조건 |
|---|---|
| `COUPLED_STRONG` | corr_20d_spx ≥ 0.6 |
| `COUPLED` | 0.3 ≤ corr < 0.6 |
| `DECOUPLED` | −0.3 < corr < 0.3 |
| `INVERSE` | corr ≤ −0.3 |

- 백테스트에서 커플링 국면별 성과를 분해한다. **유의미한 차이가 나오면** `검증_결과.md`의 "검증 대기 목록"에 매크로 게이트 반영 후보로 등재. **차이 없으면 기록만 유지.**

## 8. 국면(Phase) — 인과적 룰 기반 4축

**시점 t의 국면은 t 이전 데이터만으로 판정한다.** 사후 라벨링("2022는 하락장이었으니까")은 look-ahead다.

| 축 | 라벨 | 기준 (고정 임계값) |
|---|---|---|
| **A 추세** | BULL / BEAR / TRANSITION | BULL: 지수>MA200 & MA200 상승 · BEAR: 지수<MA200 & MA200 하락 |
| **B 변동성** | VOL_LOW / MID / HIGH | 20일 실현변동성(연율)의 **과거 3년 롤링 분위수** 33% / 67% |
| **C 커플링** | COUPLED_STRONG / COUPLED / DECOUPLED / INVERSE | §7 |
| **D 드로다운** | DD_NONE / DD_CORRECTION / DD_BEAR | 전고점 대비 <5% / 5~20% / >20% |

### ⚠️ KOSPI 지수 경로를 '재구성'한 이유 (정직하게)
실측 지수 파일(`kospi_index_daily.csv`)이 **2011-08에서 잘려 있고 마지막 행이 손상**되어 있다.
2011~2023 (약 11.8년)이 비어 있어 백테스트 구간 대부분이 공백에 걸린다.

- **공백을 보간하면 그게 가짜 데이터다. 절대 안 했다.**
- 대신 `시장영향_검증_kospi_raw.csv`의 **실측 일간수익률(`y_same`, 1996~2026 연속)** 을 누적해 경로를 만들었다.
- 이것은 보간·추정이 아니라 **관측된 실수익률의 정확한 변환**이다.
- 국면 판정 지표(MA200 교차, MA200 기울기 부호, 드로다운 %, 실현변동성)는 **전부 스케일 불변**이므로 레벨의 절대값은 무관하다.
- **검증**: 겹치는 구간(2023-06~2026-06, n=739)에서 재구성 수익률 vs 실측 지수 수익률 **상관 0.9991**, 평균절대오차 0.0027%p.
- **한계**: 누적 3년 경로 오차 약 3.3%. **레벨 자체는 신뢰하지 말 것.** 본 용도에는 영향 없음.

### ⚠️ 국면 분해의 함정 (결과 문서에도 명시)
> **국면을 쪼갤수록 각 구간 표본이 줄어 노이즈가 커진다. "어떤 국면에서 잘 되더라"는 결론은 대부분 우연일 수 있다. 국면 분해는 가설 생성용이지, 그것만으로 규칙을 바꾸는 근거가 될 수 없다.**

n < 30 셀은 **"통계적 결론 불가"**로 명시한다.

## 9. 파라미터 근거

→ **`검증/파라미터_근거표.md` 참조.** 여기 요약만:

- ✅ **원문 확인**: 처분효과(Odean 1998, PGR 0.148 vs PLR 0.098, t>35), 할로윈(Bouman & Jacobsen 2002), 아노말리 감쇠(McLean & Pontiff 2016, 발표후 −58%)
- ⚠️ **실무서 출처**: ATR(Wilder 1978), 2%룰(Elder — Van Tharp는 1% 권고)
- ❌ **근거 미확인 (관행/휴리스틱)**: ATR 2.5배·1.5배, 시간손절 20일/10일, MA 20주/20일, 종목상한 10%, 트랙 70:30, regime 노출배수, 커플링 임계, 국면 임계
- ❌ **주장 자체가 출처 미확인**: "dual MA > triple MA", "추세추종 승률 35~45%" → **설계 근거로 쓰지 말 것**

> **전략의 핵심 숫자 대부분은 학술 근거가 없다. 이것이 이 시스템의 가장 큰 약점이다.**
> 근거가 있는 건 "손실을 자르고 이익을 달리게 하라"는 **방향성**뿐이다.
> **구체적 숫자는 전부 관행이므로, 백테스트가 그 자리를 벌어줘야 한다.**

## 10. 검증 체계 (투 트랙 검증)

> ⚠️ 여기서 "트랙"은 **검증 방법**이다. 매매 트랙(L/S)과 혼동 금지.

| | 검증① 통합(Pooled) | 검증② 국면별(Conditional) |
|---|---|---|
| **성격** | **결론의 기본선** | **가설 생성용** |
| **내용** | 전 구간 하나로. 통계검정(t, p, CI) | 4축 분해. 모든 셀에 n 표기 |
| **여기서 무효면** | **기본적으로 기각 방향** | 결론 도출 불가 |

### 교차 판정표

| | 국면별 ✅ 안정 | 국면별 ❌ 불안정 |
|---|---|---|
| **통합 ✅ 유효** | **채택 후보** (강한 증거) | **조건부 채택** — "국면 의존성 있음" 경고 병기 |
| **통합 ❌ 무효** | **기각** — 데이터마이닝 의심 | **기각** |

> **핵심**: "통합에서는 안 먹히는데 특정 국면에서만 먹힌다" → 발견이 아니라 **과최적화 신호**다.

- **다중검정 보정 필수**: 국면 4축 × 파라미터 격자 × 매매트랙 2개 = 수십~수백 검정 → Bonferroni(α = 0.05 / 검정수). 보정 전/후 p값 병기.
- **최종 판정은 OOS 기준.** IS 성과는 참고치.
- 모든 채택/기각은 `검증/채택기각_로그.csv`에 기록. **이것이 학습 루프의 핵심 자산이다.**

## 13. 이 시스템의 한계 (정직하게)

1. **백테스트가 벤치마크(코스피 buy&hold)를 이기지 못했다.** → `백테스트_결과.md` 참조. 매도규칙서 v2도 같은 결론을 이미 기록하고 있다.
2. **생존편향 + 유니버스 선택편향**이 존재한다. 제거 못 했다. 결과는 **실제보다 낙관적**이다.
3. **표본이 짧고, 그 기간이 강세장이었다.** 추세추종은 강세장에서 잘 보이게 되어 있다. **하락장 검증이 사실상 없다.**
4. **파라미터 대부분이 근거 없는 관행값**이다 (§9).
5. **실전 ≠ 백테스트**: 매크로 게이트가 백테스트에 미적용.
6. **코스닥 테마연동 미적용.**
7. **VKOSPI 데이터가 멈춰 있다** (2026-06-05).

> **이 백테스트의 올바른 용도: "이 규칙이 명백히 망가졌는지" 확인하는 것.**
