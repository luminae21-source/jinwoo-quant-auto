## 문제

`jq_discover.py`가 후보 **순위**를 이렇게 매긴다:

```
안정모드 score = (1−손절폭)*100 + (자금유입−1)*15 + (테마 10)
돌파모드 score = (자금유입−1)*40 + 이격도*20 + (테마 10)
```

→ **모멘텀(RS)·자금유입·이격도** 중심. 그런데:
- C(전 시장) 검정: **모멘텀·52주고가 = 기각.** 저변동성·저PBR = 채택.
- ② 섹터 내 검정: **저PBR·저변동성이 진우 사냥터 안에서도 OOS로 이김.**

**검증된 기울기가 순위에 하나도 안 들어가 있다.** 검증한 걸 실전 툴이 안 쓴다.

## 바꾸는 것 — 순위 점수에만 기울기 추가

**진우님의 상태필터는 안 건드린다** (추세>MA200·유동성·과열제외·손절 사이징 = "대응" 철학·리스크 통제).
바꾸는 건 **동점 후보를 어느 순서로 보여주냐**뿐.

후보 DataFrame이 만들어진 뒤, 후보들 **사이에서** 횡단면 순위로:

```
저변동성_선호 = 1 − rank_pct(60일 변동성)     # 덜 출렁일수록 ↑
저PBR_선호    = 1 − rank_pct(PBR)             # 쌀수록 ↑  (PBR 없으면 0.5=중립, 벌점 없음)
기울기 = (0.4·저변동성_선호 + 0.6·저PBR_선호) × 25
score += 기울기
```

- **가중 0.6:0.4로 저PBR을 더** — ②에서 저PBR이 우세(OOS t 3.17 vs 2.68)였으니.
- 최대 +25점 — 테마(+10)·자금유입과 **비슷한 크기**. 지배하지 않고 **밀어주기만**.
- PBR 결측은 **중립(0.5)** — 벌주지 않는다(재무 커버리지 한계 반영).
- **섹터 분산 캡(같은 섹터 최대 2종목)·top N 그대로.**

## 왜 곱하기 아니고 더하기

기존 score를 곱셈으로 스케일하면 트렌드/유동성 통과분이 왜곡된다. 더하기는
"통과한 후보들 중 검증된 특성을 가진 쪽을 위로"라는 의도를 정확히 구현한다.

## 투명성

- `--no-tilt` 플래그로 끌 수 있다(배선 전후 A/B 비교용).
- 출력에 **PBR·변동성60** 컬럼 추가 → 진우님이 왜 위로 왔는지 눈으로 확인.
- docstring에 근거(C·②) 명시.

## 한계 — 정직하게

- ②는 **조건부**(IN 관문 미달). 그래서 기울기는 **지배가 아니라 밀어주기**로 제한.
- PBR은 최신 스냅샷(라이브 발굴이라 PIT 불필요, 단 분기 지연 존재).
- 저변동성 기울기는 진우님 고변동성 스타일과 상충할 수 있음 → **가중 낮게(0.4)**,
  상태필터가 이미 초고변동을 걸러줌(STOP_MAX 15%).

## 검증

- 셀프테스트에 기울기 항목 추가(저변동성·저PBR 후보가 실제로 위로 오는지).
- 배선 전후 발굴후보 상위 비교(같은 날, --no-tilt vs 기본).
