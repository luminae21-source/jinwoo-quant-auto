# 수정주가(기업행위 조정) 월봉 재수집 — 실행 계획

작성 2026-07-26 · 목표: `_월봉종가캐시_KOSPI/KOSDAQ.csv`를 **기업행위 조정 월봉**으로 재구축하되, **생존편향 제거(상폐 포함)를 최대한 지킨다.**

## 0. 왜 어려운가 (핵심 제약 — 먼저 인지)

| 요구 | 필요한 pykrx 호출 | 문제 |
|---|---|---|
| **생존편향 제거**(상폐 포함) | `get_market_ohlcv(날짜, market)` — 그날 거래된 전 종목 | 날짜별 = **미조정** 가격만 나옴 (지금 캐시가 이래서 미조정) |
| **수정주가** | `get_market_ohlcv_by_date(from,to, 종목, freq='m', adjusted=True)` — 종목별 | 종목별 = ISIN 필요 → **상폐 ~2,500종목이 실패** |

**결론:** 둘을 동시에 100% 만족하는 단일 경로는 없다. → **하이브리드 + 상폐 처리 결정**이 계획의 중심.

## 1. 단계 (Phase)

**Phase 0 — 실현가능성 스모크 (10분, 먼저 반드시)**
- `collect_adjusted_monthly.py --smoke` 로 PC에서 확인:
  - (a) **상장 종목** 월봉 수정주가 정상 수신? (예: 005930)
  - (b) **상폐 종목** 코드로 `adjusted=True` 호출이 되나/안 되나? (예: 과거 상폐코드 1~2개)
- **판정:** (b)가 되면 → 상폐도 종목별 수집. 안 되면 → 상폐는 미조정 유지 + `ca_guard` 윈저(3-B).

**Phase 1 — 상장 종목 수정주가 월봉 (본수집, ~20~40분)**
- 유니버스 = 현재 상장(`get_market_ticker_list(오늘, KOSPI/KOSDAQ)`) ∪ 캐시에 있는 코드 중 수신 가능한 것.
- 각 종목: `get_market_ohlcv_by_date("19960101","오늘", 종목, freq="m", adjusted=True)` → 월말 종가.
- **체크포인트·재개·sleep·재시도**(네 기존 수집기 패턴 재사용). 월봉이라 종목당 1콜 → 콜 수 ~2,600.
- 산출: `_월봉종가캐시_KOSPI_adj.csv`(+KOSDAQ), 컬럼 `code,ym,close` (기존과 동일 스키마).

**Phase 2 — 상폐 종목 처리 (Phase 0 결과에 따라)**
- **2-A (상폐도 수신 가능 시):** 상폐 코드 목록 확보 → 종목별 adjusted 수집. 상폐 코드는 캐시의 `기존 코드 − 현재상장 코드`로 도출.
- **2-B (불가 시, 현실적 기본):** 상폐는 **미조정 유지**하되 `ca_flags.csv`로 CA월 표시 + `ca_guard.winsor_returns`로 크기왜곡만 차단. 문서에 "상폐 부분 미조정" 명시.

**Phase 3 — 병합·검증 (`validate_adjusted.py`)**
- 합격 기준:
  - [ ] 조정 캐시에 **정수배 점프(ca_flags 유형) ≈ 0** (상장분)
  - [ ] `kospi_monthly_prices.csv`(그라운드트루스, 2010+·1243종목)와 **월수익 큰불일치(>50%p) 대폭 감소**(현 raw 380 → 목표 <50)
  - [ ] 옛 캐시와 **CA월에서만 차이**, 그 외 월 일치
  - [ ] 종목수·기간·행수 = 기존과 유사(상폐 포함 4,000+)

**Phase 4 — 영향 재추정 (숫자 갱신)**
- 조정 캐시로 `factor_efficacy`·유니버스 규칙화·CAGR 백테 재실행 → **롱숏·CAGR이 얼마나 바뀌는지 정량**.
- 백서 4·9장의 "크기 잠정" 딱지를 **확정치**로 교체(또는 변화 반영).

**Phase 5 — 컷오버**
- 옛 캐시 → `_raw` 백업(`data_snapshot.py` 활용). 조정본을 정본으로 스왑.
- `진우_일봉_증분수집.py`(주간 증분)도 **adjusted 인지**로 갱신 — 단, 증분은 날짜별(전종목)이라 미조정 → **월 1회 상장분 종목별 adjusted 재빌드**를 유니버스 월초 작업에 추가하는 방식 권장.

## 2. 리스크·대응

- **pykrx 레이트리밋/차단:** sleep 0.3~0.8s + 지수백오프 재시도 + 체크포인트(중단돼도 재개). 야간 실행 권장.
- **상폐 커버리지 손실(2-B):** 조정 불가분은 미조정+윈저로 "크기왜곡 차단"까지만. 완전 조정은 DART 기업행위 팩터가 필요(별도 과제).
- **adjusted 정의 차이:** KRX 수정주가는 분할·병합 반영, 배당은 미반영(총수익 아님) — 우리 팩터는 가격수익 기준이라 정합.
- **월말 정렬:** freq='m'는 월말 영업일 기준 — 기존 캐시 규칙과 동일한지 Phase 3에서 대조.

## 3. 산출물 (이 계획으로 만들 것)

1. `collect_adjusted_monthly.py` — 수집기(PC용, --smoke/--self-test/--resume) ✅ 동봉
2. `validate_adjusted.py` — 검증기(정수배점프·그라운드트루스·옛캐시 대조) ✅ 동봉
3. `_월봉종가캐시_KOSPI_adj.csv` / `_KOSDAQ_adj.csv` — 수집 산출(PC에서 생성)
4. 영향 리포트 + 백서 4·9장 숫자 갱신

## 4. 소요·순서

- Phase 0: 10분 (오늘 바로) → Phase 1: 20~40분 (야간) → Phase 2: 상폐수 따라 +10~60분 → Phase 3~4: 30분 → Phase 5: 15분.
- **먼저 Phase 0 스모크만 돌려 (a)(b) 결과를 알려줘** — 상폐 수신 가능 여부가 전체 범위를 정한다.
