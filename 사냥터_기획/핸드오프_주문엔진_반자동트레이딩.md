## 0. 배경 (한 문단)
진우 사냥터 = 한국주식 딥밸류 바닥 발굴 시스템(30년·상폐반영·IN/OOS 검증 완료). 핵심 엣지 = **딥밸류바닥**(저PBR 하위20% ∩ 이격도<0.85 ∩ 20일수익>0), 분산 10~15종·장기보유(2~3년)·강함에 익절(이격≥1.5·+100%·PBR≥1.0). 검증 종합: `사냥터_기획/진우_사냥터_검증종합_한장.md`.
발굴툴이 매일 후보를 `진우_타점발굴.csv`로 뱉는다. **이 트랙의 일 = 그 신호를 실제 주문으로 바꾸고, 안전하게 반자동→자동으로 올리는 것.**

## 1. 이 트랙의 목표
"보조적이지만 실질 자동" = **엔진이 오늘의 정확한 주문(뭘·몇 주·얼마·손절)을 생성하고, 사람은 승인만.** 완전 무인은 라이브 실적·비용검증 후에만.

## 2. 이미 만든 것 — `진우_주문생성.py` (현재 상태)
- 입력: `진우_타점발굴.csv`(후보) + 자본(--capital 또는 `진우_모의매매장.csv`의 입금) + 보유현황.
- 로직: 딥밸류바닥 우선, N종(기본 12) **등가중** 분산, 종목당 = 자본/N, 현금 한도 내, 보유·중복 제외.
- 출력: 콘솔 + `진우_주문생성_현황.html` (종목·수량·매수가·금액·비중·손절).
- 옵션: `--capital 10000000 --n 12 --include-bounce`. 셀프테스트 `--self-test`(3/3).
- 자동갱신 파이프라인(`진우_자동갱신_파이프라인.bat`)에 포함됨(매주 재생성).
- **미구현(다음 할 일)**: 매도/익절 주문 생성, 1%리스크 사이징 옵션, 섹터/그룹 캡 강제, 증권사 API 연동.

## 3. 안전 로드맵 (순서 절대 준수)
1. **[현재] 주문 제안 + 사람 집행** — 엔진 생성 → 진우 확인 → 수동 주문(또는 모의매매로 연습).
2. **[3~6개월] 라이브/모의 전진 기록** — 제안대로 했을 때 실제 결과 추적. 백테스트를 라이브가 확증해야 다음 단계.
3. **[검증 후] 비용·유동성 완비 체크** — 슬리피지·세금·체결가 반영해도 시장을 이기는지.
4. **[그 후] 증권사 API 연동(반자동)** — 엔진이 주문 생성 → **사람이 승인 버튼** → API가 집행. 무인 방아쇠 아직 없음.
5. **[장기·신중] 완전 무인** — 오랜 라이브 실적 + 리스크 차단기(일일 손실 한도·킬스위치) 갖춘 뒤에만.
- **넘지 말 것**: 검증 안 된 전략을 무인 자동으로 돌리기 = 돈 잃는 가장 빠른 길.

## 4. 다음 작업 후보 (우선순위)
1. **매도/익절 주문 생성** — 보유 중 익절검토(이격≥1.5·+100%·PBR 적정권) 신호 종목의 매도 주문 생성. (`진우_모의매매.py`의 signals() 로직 재사용)
2. **사이징 옵션 확장** — 등가중 외에 "1%리스크"(1R=매수가−손절, 수량=자본×1%÷1R), 확신도 가중.
3. **분산 캡 강제** — 섹터당 2종·같은 그룹 1종(예: 에코프로 계열) 자동 차단. (`진우_안전보유_점검.py`의 GROUPS 참고)
4. **증권사 API 설계** [PC 전용] — 한국 리테일: 한국투자증권 KIS Developers(REST, 추천·신식), 키움 OpenAPI+(구식·32bit), LS증권 xingAPI. **주문 생성→사람 승인→집행** 구조. 페이퍼(모의투자) 계좌부터.
5. **리스크 차단기** — 일일 최대 손실·최대 포지션·킬스위치(무인 단계 전제).

## 5. 데이터/파일 구조
- `진우_타점발굴.csv` (발굴툴 산출) — 컬럼: `star,code,name,ap,order,pbr,deep,bounce,ext,r20,c,buy,stop,resist,vflag,tag`. `deep=1`=딥밸류바닥, `bounce=1`=바닥반등, `c`=현재가, `buy`=매수타점, `stop`=손절.

- `진우_주문생성.py` / `진우_모의매매.py` — 이 트랙의 핵심 스크립트.
