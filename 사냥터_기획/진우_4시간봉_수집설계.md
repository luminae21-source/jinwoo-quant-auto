# 4시간봉 섹터 스캔 — 수집 설계 (정직한 제약 + 실행 경로)

*2026-07 · 인트라데이(장중) 4H 데이터 수집·활용 설계. 투자자문 아님.*
*목표(진우): 4시간봉으로 섹터 전반을 스캔. 현재 일봉 스캔(진우_섹터스캔.py)의 로직을 4H 종가로 교체.*

## 0. 먼저 — 정직한 제약 3가지
1. **지금 우리 데이터엔 인트라데이가 없다.** 종목일봉_30년(일봉)까지만 보유. pykrx도 분/시간봉 미제공.
2. **한국 정규장 = 09:00–15:30 = 6.5시간** → "4시간봉"은 하루에 딱 떨어지지 않음. 실무 정의 필요(§2).
3. **과거 인트라데이 '히스토리 깊이'가 얕다(핵심).** 증권사 API 분봉은 대개 **최근 며칠~수개월**만 제공 → **4H 백테스트(IN/OOS)는 사실상 불가**, 유료 벤더(코스콤 등) 없이는. 그래서 4H는 **백테스트가 아니라 '전방 축적 모니터링'**으로 설계한다(오늘부터 매일 쌓기).

## 1. 소스 선택
| 소스 | 인트라데이 | 접근성 | 히스토리 | 비고 |
|---|---|---|---|---|
| **한국투자증권 KIS REST** | 분봉(1/3/5/10/15/30/60) | REST·크로스플랫폼·무료(계좌) | 얕음(최근분) | ★1순위. appkey/secret→토큰 |
| 키움 REST(신) | 분봉 | REST | 얕음 | 대안 |
| 키움 OpenAPI+ | 분봉·틱 | OCX(윈도우 전용) | 중간 | 설치·32bit 제약 |
| LS(이베스트) xingAPI | 분봉·틱 | Windows | 중간 | |
| 코스콤 데이터몰(유료) | 과거 분봉 전체 | 구매 | 깊음 | 백테스트하려면 이 경로 |

→ **권장: KIS REST로 30분봉을 받아 4H로 집계**, 매일 전방 축적. 과거 백테스트가 꼭 필요하면 코스콤 유료.

## 2. 4시간봉 정의 (KR 6.5시간 세션)
- **2봉/일 방식(권장·단순)**: 봉1 = 09:00–13:00(4h), 봉2 = 13:00–15:30(2.5h·마감봉). "오전/오후" 2봉.
- 대안: 60분봉 6.5개 → 4H 리샘플은 경계 애매 → 2봉/일이 실무적으로 깔끔.
- 각 봉: open=구간첫가, high/low=구간극값, close=구간끝가, volume=합. **스캔은 close만 필요**(일봉 스캔과 동일 로직).

## 3. 스캔 로직 재사용 (설계의 핵심)
진우_섹터스캔.py는 "종목별 종가 배열"만 입력받아 이격(MA200)·턴(20봉)·과매도·저PBR로 섹터 집계. **입력을 일봉 종가 → 4H 종가로 바꾸면 그대로 4H 섹터 스캔이 된다.**
- 4H 기준 지표 환산: MA'200봉' = 약 100거래일(2봉/일). 턴 '20봉' = 약 10거래일. → 4H에선 더 민감(단기 바닥 반응 빠름).
- 일봉 스캔 = 중기 바닥, 4H 스캔 = 단기 바닥 → **가바닥/진바닥 다중시간축**과 자연 연결(단기 4H 저점 vs 일·주·월봉 저점 정렬 확인).

## 4. 실행 경로 (권장 순서)
1. **지금**: 일봉 섹터 스캔(진우_섹터스캔.py) 사용 — 이미 작동. 4H가 생기기 전까지 본체.
2. **KIS 키 발급**(진우 PC): 한국투자증권 계좌 → KIS Developers 앱등록 → appkey/appsecret.
3. **fetch_4시간봉_KIS.py**(스켈레톤 제공): 30분봉 수집→4H 집계→종목별 CSV 축적(매일 실행, 전방 누적).
4. **N개월 축적 후**: 진우_섹터스캔.py의 입력을 4H CSV로 스위치(=4H 섹터 스캔 가동). 로직 그대로.
5. 백테스트가 필요하면: 코스콤 등 과거 분봉 구매 후 동일 파이프라인에 주입.

## 5. 한계·주의
- **4H 스캔은 예측력 검증 불가(히스토리 부족)** → 일봉/월봉에서 검증된 규칙(딥밸류·물타기·이격익절)을 4H로 '조기 관찰'만. 4H에서 새 알파 주장 금지(표본 부족).
- 섹터 예측은 이미 기각(ρ≈0) → 4H도 '군집 모니터링'용, 섹터 베팅 아님.
- 인트라데이는 노이즈·호가공백 큼 → 소형주 4H는 특히 신뢰 낮음(유동성 상위 위주).
