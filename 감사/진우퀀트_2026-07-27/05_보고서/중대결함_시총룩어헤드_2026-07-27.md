## 1. 결함의 내용

`종목시총_30년.csv`의 date는 **월말 스냅샷**이다:

```
1996-01-31, 1996-02-29, 1996-03-29, ...
```

백테 코드는 이 시총으로 **같은 달의 수익률**을 계산한다.
`유니버스_리더십로테이션.py` (동일 패턴이 `유니버스_규칙화_검정.py`에도 존재):

```python
for t in months:
    i = list(rets.index).index(t)
    mc = mcap.loc[t].dropna().sort_values(ascending=False)   # ← 당월말 시총

    w = px.iloc[i-13:i-1]; mom = (w.iloc[-1]/w.iloc[0]-1)    # ← 모멘텀은 정상 시차 ✅
    sel = list(mom.sort_values(ascending=False).index[:N])
    cur = rets.loc[t]                                        # ← 당월 수익
    out.append(cur[names].mean() - 비용)
```

**월말 시총으로 그 달 종목을 고른다.** 그 달에 오른 종목이 사후에 큰 시총을 갖게 되므로
**자동으로 승자를 선택**하게 된다.

### 왜 아무도 못 봤나
**모멘텀 창은 시차 처리가 정확하다**(`px.iloc[i-13:i-1]` — 12-1 모멘텀, 최근월 제외).
코드가 룩어헤드를 의식하고 있다는 인상을 주기 때문에, 시총 pool 쪽은 검토에서 빠졌다.
`--self-test 6/6`도 이 축은 검사하지 않는다.

## 5. 교정 방법

```python
# 모든 백테 스크립트에서
M = mcap.pivot_table(...)
M = M.shift(1)          # ← 전월말 시총으로 당월 편입 결정
```

또는 수집 단계에서 시총 date를 **다음 달로 라벨링**한다(1996-01-31 스냅샷 → 1996-02 편입용).

### self-test 추가 항목
```
· 시총 인덱스 t의 스냅샷 시각 < 수익률 t의 시작 시각인가
· 시총 shift 전후 CAGR 차이가 3%p 이내인가 (초과 시 룩어헤드 경보)
```
**두 번째 검사는 룩어헤드 탐지의 범용 도구다** — 어떤 선택 변수든 shift(1)을 넣었을 때
성과가 급락하면 그 변수는 미래 정보를 담고 있다.
