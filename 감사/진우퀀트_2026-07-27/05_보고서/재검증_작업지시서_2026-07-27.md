# PART A — 지금 당장 해야 할 재검증 (우선순위)

## 🔴 A-1. 베이스라인 정체 규명 ← **최우선, 다른 모든 것의 전제**

### 문제
`TOP30_고정 EW = 19.8%` vs `KOSPI = 6.9%` → **연 12.9%p 갭.**
시총 상위 30종목을 동일가중으로 보유만 했는데 지수를 30년간 연 12.9%p 이겼다는 뜻.

**설명 가능한 요인 합계로는 절반도 안 된다:**

| 요인 | 기대 기여 |
|---|---|
| 배당 (KOSPI PR 지수라면) | +1.5~2.0%p |
| 동일가중 리밸런싱 프리미엄 | +1.0~3.0%p |
| **합계** | **+2.5~5.0%p** |
| **실측 갭** | **+12.9%p** |
| **미설명** | **약 8~10%p** |

### 유력 원인 — 시총 데이터 스냅샷 근사
7/23 판정문 §6-5가 이미 경고: *"상폐포함이나 시총·유동성 필터는 현재 스냅샷 근사 잔존"*

`종목시총_30년.csv`가 **현재 시점 기준 시총을 소급 적용**한다면,
"1996년 시총 top30"이 실제로는 **"2026년 기준 큰 회사들의 1996년"**이 된다.
= look-ahead + 생존편향. 정확히 이런 비현실적 베이스라인을 만드는 메커니즘이다.

### 부호 역전 증거
| 데이터 | 기간 | top30 | KOSPI | 부호 |
|---|---|---|---|---|
| 미조정 | 1996~2026 | 19.8% | 6.9% | **+12.9%p** |
| 조정본 | 2015~2026 | 5.4% | 13.8% | **−8.4%p** |

배당 롱숏이 −2.5%→+3.4%로 뒤집힌 것과 동일 패턴. 그때 원인은 수정주가였다.

### 검증 절차 (순서대로)
1. **시총 데이터 PIT 확인**
   ```
   # 종목시총_30년.csv 스키마 확인 — date별로 값이 실제 변하는가?
   # 상폐 종목이 상폐 이전 시점에 존재하는가?
   # 특정 과거 월(예 1999-12)의 top30 명단을 뽑아 당시 실제 대형주와 대조
   ```
   1999년 top30에 카카오·셀트리온·에코프로가 들어있으면 **즉시 확정**.

2. **KOSPI 벤치 정의 확인** — PR인가 TR인가. PR이면 배당 ~2%p 보정 필요.

3. **동일가중 프리미엄 단독 측정** — 같은 유니버스를 시총가중으로 돌려서 EW-CW 차이만 분리.

4. **상폐 종목 실제 포함 여부** — `audit_data_coverage.py` [C] 항목.
   중도소멸 비율 5% 미만이면 생존편향 확정.

### 판정
- 시총이 PIT가 아니면 → **19.8%·20.1%·21.7% 전부 무효.** 3장 전체 재산출.
- PIT가 맞고 갭이 유지되면 → 한국시장 EW 프리미엄이 실재한다는 별도 발견(중요).

# PART B — 백서를 "재검증 가능"하게 만드는 구조

## B-1. 모든 수치에 재현 블록 부착 (필수 5요소)

현재 백서는 숫자만 있고 **재현 경로가 없다.** 각 수치에 아래를 붙인다:

```markdown
| 항목 | 값 |
|---|---|
| 수치 | 20.1% (순 CAGR) |
| **클레임 ID** | C-003 |
| **스크립트** | `강화키트\유니버스_규칙화_검정.py` |
| **데이터 스냅샷** | `_월봉종가캐시_KOSPI/KOSDAQ.csv` (sha256 앞12) + `종목시총_30년.csv` |
| **명령어** | `py 유니버스_규칙화_검정.py --label R0` |
| **기간·유니버스** | 1996-01~2026-07 (329M) · 시총 pool100 |
| **대조군** | TOP30_고정 EW (19.8%) ← KOSPI 아님 |
| **기대값·허용오차** | 20.1% ± 1.0%p |
| **최종 재현일** | (미실행) |
```

**허용오차와 대조군을 명시하는 것이 핵심.** 이게 없으면 "재현했다"를 판정할 수 없다.

## B-2. `기준값.json` — 숫자의 단일 진실

```json
{
  "generated_at": "2026-07-27T11:49:00+09:00",
  "data_hashes": {
    "월봉_KOSPI": "a1b2c3...",
    "시총_30년": "d4e5f6..."
  },
  "claims": {
    "C-001": {"value": 3.4,  "unit": "%/yr", "status": "active",
              "script": "mini_factor_adj.py", "period": "2015-2026",
              "benchmark": null, "tolerance": 0.3},
    "C-003": {"value": 20.1, "unit": "%/yr", "status": "disputed",
              "script": "유니버스_규칙화_검정.py", "period": "1996-2026",
              "benchmark": "C-019", "tolerance": 1.0},
    "C-019": {"value": 19.8, "unit": "%/yr", "status": "under_review",
              "note": "KOSPI 대비 +12.9%p — 설명 가능 요인 초과. A-1 조사 중"}
  }
}
```

백서·대시보드·세션정리가 이 파일에서 렌더링한다 → **문서 간 불일치 원천 봉쇄.**

## B-3. 빌드 게이트

`백서_빌더` 마지막에 삽입:
```
py audit_whitepaper.py 진우퀀트_백서.md --registry 클레임_레지스트리.csv || exit 1
py verify_all.py || exit 1
```
무마킹 폐기클레임이 1건이라도 있으면 **산출물을 만들지 않는다.**

## B-4. 재현 로그

각 클레임의 마지막 재현 일자를 기록하고, **90일 초과 시 백서에 자동으로 ⏳ 배지**.
"6개월 전에 한 번 돌린 숫자"와 "어제 재현된 숫자"를 독자가 구분할 수 있어야 한다.

## B-5. self-test 확대
`유니버스_규칙화_검정.py --self-test`가 이미 6/6 있다. 여기에 추가:
- 시총 데이터 PIT 검사 (미래 상장 종목이 과거에 없는지)
- 상폐 종목 존재 검사
- 벤치마크 가중방식 일치 검사
