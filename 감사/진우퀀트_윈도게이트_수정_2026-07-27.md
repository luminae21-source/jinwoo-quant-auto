## 1. 원인 — 파이프로 넘어갈 때만 cp949로 죽는다

```
[G3] audit_whitepaper.py  — exit=1
[G4] lookahead_shift_test.py  — 탐지 ?%p (exit=1)
```

`G4`의 `?%p`가 결정적 단서다. 정규식이 출력에서 숫자를 못 찾았다 = **자식이 아무것도 못 찍고 죽었다.**

윈도 파이썬은 stdout이 **콘솔**이면 콘솔 코드페이지를, **파이프**면 `locale.getpreferredencoding()`
(한국어 윈도 = **cp949**)를 쓴다. 게이트는 `subprocess.run(capture_output=True)`로 자식 출력을
파이프로 받으므로, 자식이 `✅` `🚨` 같은 문자를 찍는 순간 **UnicodeEncodeError → exit 1**이 된다.

> **그래서 "손으로 돌리면 되는데 게이트로만 실패"하는 형태로 나타났다.**
> 네가 `py audit_whitepaper.py ...` 를 직접 치면 콘솔이라 멀쩡하고,
> 게이트가 부르면 파이프라 죽는다. PowerShell UTF-8 프로필도 이건 못 막는다 —
> 프로필은 **콘솔** 인코딩을 바꿀 뿐 자식 프로세스의 **파이프** 인코딩은 안 건드린다.

`G5`가 통과한 이유도 같은 논리다 — `MAXDELTA=0.5` 같은 ASCII만 찍었으니까.

## 2. 수정 (2중 방어)

**① 게이트가 자식에게 UTF-8을 강제한다** — 근본 수정

```python
def child_env():
    e = dict(os.environ)
    e["PYTHONIOENCODING"] = "utf-8"
    e["PYTHONUTF8"] = "1"
    return e

subprocess.run(..., env=child_env())
```

**② 스크립트 15종에 자체 가드 추가** — 게이트 밖에서 파이프로 쓰일 때 대비

```python
try:
    import sys as _sys; _sys.stdout.reconfigure(encoding="utf-8")
except Exception:
    pass
```
