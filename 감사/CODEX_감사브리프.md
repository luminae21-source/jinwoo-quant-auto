# 진우퀀트 — Codex 코드 감사 브리프

> **사용법:** 리포를 Codex에 연결(비밀키 제거 체크리스트 **먼저** 통과) → 이 파일 전체를 Codex 작업 지시로 붙여넣기. `엔트리포인트_지도.md`도 함께 첨부하면 길잡이가 된다.

---

## 역할

너는 계량금융 시스템을 감사하는 **냉정한 시니어 퀀트 엔지니어**다. 이 리포(진우퀀트, 한국주식 개인 퀀트, ~293개 파이썬 모듈)를 **읽고·실행·추적**해서, "서술된 방법론이 코드에 실제로 올바르게 구현됐는가"를 검증하라. 칭찬이 아니라 결함을 찾는 적대적(red-team) 관점. 발견은 **파일·라인·근거**로 명시하고, 추측과 확인을 구분하라.

`엔트리포인트_지도.md`로 어디를 볼지 잡고, `데이터수리\mini_factor_ic_v2_1.py`처럼 자체완결로 도는 것부터 실행해 감을 잡아라. (네트워크는 꺼져 있으니 pykrx 수집은 실행 불가 — 코드 정합성 위주로.)

## 감사 7축 — 각 축마다 판정(✅타당/⚠️의심/❌결함) + 파일·라인 근거

**A. 룩어헤드(look-ahead)**
- 재무를 가격과 **같은 달에 병합**하는 곳이 있나? 공시시차(PIT) 없이 미래 재무를 쓰나?
- 팩터·백테에서 `shift`/리밸런싱 타이밍이 미래 정보를 참조하나?
- `pit_lag.py`가 실제 백테에 적용되나, 문서상으로만 있나?

**B. 생존편향**
- `fetch_stock_panel_30y.py`의 "날짜별 전종목 수집"이 상폐 포함을 실제로 보장하나?
- 팩터·백테가 **현재 상장 종목만** 은연중에 쓰는 필터가 있나(생존편향 재유입)?

**C. 기업행위/데이터 품질 (★중점)**
- 백테·롱숏·CAGR이 `_월봉종가캐시_*.csv`의 **미조정 raw close**를 그대로 복리계산하나?
- `데이터수리\ca_flags.csv`(정수배 점프 3,765건)를 감안하면 CAGR/롱숏 "크기"는 얼마나 신뢰 가능한가?
- `ca_guard.py`(윈저) 적용이 실제 계산 경로에 붙어 있나?

**D. 비용·다중검정·과최적**
- `진우_비용모델.py`의 회전율×(매도세+슬리피지)가 **실제 백테 수익에서 차감**되나?
- 다중검정보정(|t|≥2.3/3.0)이 코드에 있나? DSR/PBO 같은 과최적 지표는?
- 사전등록 합격선이 **사후 조정**된 흔적(하드코딩된 임계값이 결과에 맞춰짐)이 있나?

**E. 재현성**
- `selftest_all.py`를 돌려 전 모듈이 초록인가? 실패는 무엇 때문인가?
- `mini_factor_ic_v2_1.py`가 예상출력과 일치하나? 팩터 IC(배당 최강)가 재현되나?
- 서술된 수치(백서 4·9장)를 코드로 **재생성**할 수 있나? 못 하면 무엇이 빠졌나?

**F. 코드 품질·안전**
- 실계좌 집행(`jq_broker_kis.py`, `진우_주문생성.py`, `진우_리스크차단기.py`)에 **주문 오류·과집중·현금초과** 방어가 견고한가?
- fail-safe 게이트(`preflight.py`, `recommend_pipeline.py`)가 STALE 데이터 발송을 실제로 차단하나?
- 하드코딩 비밀키·명백한 버그·예외 미처리?

**G. 종합 수준 평가**
- 이 코드베이스의 수준을 **(개인/학술/기관 퀀트)** 대비로 한 문단. 백서 자체등급(검증방법론 A−·자동화 A−·정직성 A·실전 D)에 **코드 근거로** 동의/반박.
- "설명은 훌륭한데 구현이 못 따라가는" 갭이 있나, 아니면 구현이 설명을 뒷받침하나?

## 산출 형식

```
[결론] 코드 근거 한 줄 판정 + 가장 치명적 결함 1 + 가장 인상적 강점 1
[축별] A~G 각 판정·근거(파일:라인)·재현결과
[재현] selftest_all / mini_factor_ic_v2_1 실행 결과 요약
[수준] 개인/학술/기관 대비 평가 + 백서 자체등급 동의/수정
[다음] 실전 전 반드시 고쳐야 할 코드 이슈 우선순위 3
```

## 경계 (정직하게 구분할 것)

- Codex는 **코드·업로드 데이터**만 본다. 원천 KRX 데이터의 정확성(미조정 등)은 코드가 완벽해도 독립 검증 불가 — "garbage-in" 가능성은 별도.
- 네트워크 off → pykrx 수집·라이브 API는 실행 불가.
- 이 감사는 **구현 정합성**이지 **실전 성과 보장**이 아니다. 트랙레코드(달력 시간)는 대체 불가.

⚠️ 정보·검증용·투자자문 아님. 실계좌 키가 포함되지 않았는지 감사 전 재확인.
