# 진우퀀트 집행 런북 — 점수부터 체결까지 한 흐름 · 2026-07-23

> 흩어진 부품(점수·사이징·RiskGuard·매도·집행)을 **하나의 파이프라인**으로 잇는 운영 절차서.
> 집행 설계(B)의 약점 = 부품은 있는데 연결·강제가 안 됨. 이 런북이 그 연결이다. 투자자문 아님·책임 진우.

## 0. 단일 진실원천
모든 한도는 `진우_통합한도.json` 하나. 코드는 `진우_한도로더.py`로 읽는다.
```
py 실행키트\진우_한도로더.py --show      # 현재 한도 확인
py 실행키트\진우_한도로더.py --self-test  # 정합성 검증
```

## 1. 본체 v3.7.2 — 월간 파이프라인 (매월 첫 영업일)

```
① py score_v37_2.py                     # 18종 점수 → S+/S/A 픽 + 권장비중
② py 실행키트\사이징_강제.py 로 비중 검토  # 종목캡15/섹터캡35 이미 엔진 반영
③ py 진우_주문생성.py                    # 픽 변화 → 매수/매도 주문안
④ py 실행키트\execute.py --broker kis --paper   # RiskGuard→승인→모의집행
⑤ py ma200_regime_check.py              # MA200 방어 상태 확인(RISK-ON/OFF)
⑥ 매도: 본체는 등급이탈 시만 청산(포지션 ATR 스톱 없음 — 매도규칙 v3 core)
```

## 2. 재량 테마 — 진입 파이프라인 (기회 발생 시)

```
① 발굴: py 진우_테마발굴.py / 진우사냥터_스크리너.py
② 진입 유형 결정: momentum(돌파) vs deepvalue(저PBR+과매도+턴)
③ 사이징: py 실행키트\사이징_강제.py
   - risk 1%(돌파 0.5%) · ATR 사이징 · heat≤6% · 동일테마≤2&40% · 동시≤5~7
④ 킬스위치 확인: lane 일−7/주−12/월−15% 도달 시 신규 정지
⑤ 주문: 진우_주문생성.py → execute.py --broker kis --paper (RiskGuard 통과+승인)
⑥ 기록: 진우_모의매매장.csv 자동 · Track W 반사실 기록(trackw_update.py)
```

## 3. 재량 테마 — 매일 보유점검 (매도 v3 라우터)

```
py 실행키트\매도규칙_라우터.py 로 유형별 판정:
  · momentum : 종가 < 고점−max(3.5ATR,25%) → 다음날 청산
  · deepvalue: 재난 −40%만 손절 · 이격≥1.5/+100%/PBR≥1.0 → 강함에 익절
  · 공통     : thesis 붕괴 → 즉시 · 20일 ±5% 횡보(모멘텀) → 검토
```

## 4. 두 방어선 (혼동 금지)

| 계층 | 모듈 | 시점 | 역할 |
|---|---|---|---|
| **전략 규모** | `사이징_강제.py` | 진입 결정 시 | 얼마나 살까 — 2%룰·heat·집중·킬스위치 |
| **집행 방어** | `진우_리스크차단기.py` (RiskGuard) | 주문 직전 | 오타·현금초과·과집중·중복 차단 |

→ 순서: **사이징_강제(규모) → 주문생성 → RiskGuard(집행 방어) → 사람 승인 → 집행.**

## 5. 실전 리스크 즉시 조치 (개선안 ⑤)

- **레버리지 43% → 15%** 이내로 축소(의사결정보드 한도초과 플래그). 신규 레버리지 금지.
- **반도체 44% → 35%** 섹터캡 실제 강제(현재 캡 초과).
- 축소분은 **현금/방어로**(다른 주식 재투자 ✗ — 운영가이드 결론).
