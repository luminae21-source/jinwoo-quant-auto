## 1. KOSDAQ 검정 결과 — 시장이 갈린다

일봉 분산일 신호, **−20% 급락 배수** (비교군 = 같은 고점권·신호 없음):

### 20일(≈4주)

| 시장 | ① 분산일 1회 | ② 10일내 2회+ | ③ 10일내 3회+ |
|---|---|---|---|
| **KOSPI** | **×2.33** (z 15.1, n 3,730) ✅ | ×1.80 (z 8.4) ✅ | ×1.68 (z 2.3) ✅ |
| **KOSDAQ** | **×1.37** (z 8.9, n 7,000) ✅ | ×1.05 (z **1.1**) ❌ | ×1.21 (z 1.5) △ |
| 전체 | ×1.76 (z 18.8) ✅ | ×1.35 (z 8.0) ✅ | ×1.47 (z 3.5) ✅ |

### 40일(≈8주)

| 시장 | ① 분산일 1회 | ② 10일내 2회+ |
|---|---|---|
| KOSPI | ×1.94 (z 15.8) ✅ | ×1.52 (z 8.1) ✅ |
| KOSDAQ | ×1.24 (z 8.3) ✅ | ×1.04 (z 1.4) ❌ |

### 세 가지 결론

**① 이 신호는 대형주(KOSPI) 도구다.** ×2.33 vs ×1.37 — 신뢰도가 1.7배 차이난다.
진우가 보는 삼성전자·하이닉스가 정확히 이 신호가 작동하는 구역이다.

**② KOSDAQ은 유의하지만 약하다.** 기저 급락률 자체가 높다(20일 8.1% vs KOSPI 3.4%).
노이즈가 커서 신호 대비 잡음비가 나쁘다. **참고용으로만 쓴다.**

**③ KOSDAQ에서 '반복 신호'는 무의미하다.** 10일 내 2회+가 z 1.1 — 정보 없음.
KOSPI에서는 z 8.4로 유효. → **도구에서 KOSDAQ은 3단계 승격 대상에서 제외**하도록 구현했다.

> **지금까지 패턴과 정반대다.** 저변동성·저PBR·하순필터는 전부 "소중형에서 작동, 대형에서 기각"이었다.
> 분산 신호는 **대형에서 작동, 소형에서 약화** — 이유는 대형주의 거래량 급증이 실제
> 기관·외국인 대량 매도를 의미하는 반면, 소형주는 작전·테마 등 원인이 뒤섞이기 때문으로 보인다(해석).

**선행성 재확인:** 분산일의 81.5%가 월~목 발생 → **평균 2.03 거래일 선행**.

## 2. 카톡 알림 배선

### 파일 3개

| 파일 | 역할 |
|---|---|
| `청산규율_알림.py` | 판정 + 메시지 생성 + 카톡 발송 (`jq_kakao` 모듈 재사용) |
| `청산규율_알림.bat` | 일봉 증분수집 → 알림 실행 (기존 SSL·인코딩 패턴 계승) |
| `청산규율_알림_예약등록.bat` | 작업 스케줄러 등록 (평일 16:10) — **관리자 권한으로 실행** |

### 발송 정책 (알림 피로 방지)

- 🟡 이상 단계가 하나라도 있으면 → **즉시 발송**
- 신규 분산일(KOSPI) 발생 → **즉시 발송**
- 전부 🟢 → **월요일만** 요약 발송
- 직전 발송과 내용이 같으면 → **생략** (`--force` 로 무시 가능)

### 시장별 차등 적용 (검정 반영)

```
KOSPI  : 1·2·3·4단계 전부 적용
KOSDAQ : 1·2단계만. 반복신호(3단계) 승격 없음 — z 1.1로 무의미하므로
```

### 실제 출력 예시 (오늘 dry-run)

```
🔍 청산규율 07/30 02:00 (기준 2026-07-27)
시장폭: 고점권 15종목 (0.15x) 🔴다이버전스
─ 보유 ─
🟢 대덕전자 109,500 (고점比-45%)
🟢 에코프로비엠 108,300 (고점比-58%)
이상 없음. 규칙대로 유지.
⚠️경보이지 매도추천 아님
```

### 설치 순서

```powershell
cd C:\Users\긍정적인_삶의자세\Desktop\진우퀀트
py 청산규율_알림.py --dry-run        # 1) 메시지 확인 (발송 안 함)
py 청산규율_알림.py --force          # 2) 카톡 실제 발송 테스트
청산규율_알림_예약등록.bat            # 3) 우클릭 → 관리자 권한으로 실행
```

**⚠️ 전제 조건 2개**
1. `jq_kakao_config.txt` 에 REFRESH_TOKEN 이 있어야 한다 (없으면 `jq_kakao_auth.py` 로 최초 1회 발급)
2. **일봉 데이터 신선도** — 알림은 `_일봉OHLCV_*_adj.csv` 만큼만 최신이다.
   현재 이 파일은 **2026-07-27 기준**. bat이 `진우_일봉_증분수집.py` 를 먼저 돌리지만,
   그 스크립트가 adj 파일을 갱신하는지 확인 필요. 아니면 **주 1회 `collect_adjusted_daily.py` 재수집**을 권한다.
